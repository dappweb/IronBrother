# IronBrother 功能测试文档

版本：v1.0  
日期：2026-05-07  
测试对象：IronBrother DApp、Admin 后台、BSC Mainnet 合约  
业务来源：`铁哥技术.xmind`、`README.md`、`contracts/IronBrother.sol`、`src/App.tsx`

## 1. 测试目标

验证 IronBrother 当前实现是否满足业务图中的核心功能：

- BSC 链 DApp 钱包连接、链上读写、语言切换。
- 入金转入 5 个收币地址轮转，并生成本金锁仓订单。
- 本金钱包带单、上午/下午场次限制、静态收益结算。
- 到期本金赎回到收益钱包、收益复投、收益提现与后台审批。
- 推荐关系、直推/团队数据、动态代数奖励、40 代白名单。
- Admin 配置、权限、暂停/恢复、用户索引和历史用户同步。

## 2. 业务功能与当前实现对照

| 业务功能 | 业务要求 | 当前实现逻辑 | 测试结论关注点 |
|---|---|---|---|
| 运行链 | BSC Mainnet 链，做成 DApp | 前端使用 BSC Mainnet；合约为 UUPS 可升级合约 | 钱包网络、错误网络提示、环境变量正确 |
| 入金 | 转到 5 个收币地址，轮换收币 | `deposit()` 调用 USDT `transferFrom` 到 `depositReceivers[nextDepositReceiverIndex]`，每次递增轮转 | 每笔收款地址、订单、余额、事件均正确 |
| 入金金额 | 100U 到 1000U，小数最多两位，本金上限 1000U | `minAmount=100 ether`，`maxAmount=1000 ether`，`maxPrincipal=1000 ether`，`amount % 1e16 == 0` | 99.99、100、1000、1000.01、两位/三位小数 |
| 本金锁仓 | 入金/补仓生成独立订单，30 天锁仓 | `_createPrincipalOrder()` 使用 `unlockAt=createdAt+lockPeriod` | 多笔入金生成多笔订单，解锁时间独立 |
| 带单时间 | 上午 9-12 点一单，下午 14-17 点一单，可调整 | `currentSession()` 按 UTC+8 判断；`stakedInSession[user][day][session]` 限制每场一次 | 开始/结束边界、同场重复、跨场可下单 |
| 静态收益 | 当前 1%，0.5%-5% 可调 | `stake()` 按当时 `yieldBps` 记录 reward；`settleStake()` 到 `settleAt` 后发放 | 收益比例、未到期不可结算、结算后不可重复 |
| 到期赎回 | 入金订单到期后，用户手动赎回到收益钱包 | `redeemPrincipal()` 到期后本金余额减少，收益余额增加 | 未到期失败、到期成功、可带单余额扣除到期未赎回订单 |
| 复投 | 收益钱包转本金钱包，生成新锁仓订单 | `reinvest()` 扣收益、加本金、生成 `PrincipalSource.Reinvest` 订单 | 余额、订单、锁仓时间、上限 |
| 提现 | 收益钱包可提现，每笔手续费默认 10U 可调 | `requestWithdrawRewards()` 冻结收益；Admin `approveWithdrawal()` 从付款钱包转账给用户和手续费地址 | 提现申请、手续费、审批、驳回恢复余额 |
| 动态奖励 | 有效门槛只用于计算有效直推和可拿代数；可拿代数内的所有下级质押流水都发放动态奖励 | `dailyStakeVolume` 累计；`settleDynamicRewardForUser(s)` 对已结束本地日手动结算 | 有效直推、低额质押、代数比例、重复结算 |
| 直推代数 | 有几个有效直推拿几代，最多 40 代 | `eligibleGeneration()`：按当天有效直推数返回代数，>=40 为 40 代 | 代数边界，白名单覆盖 |
| 40 代白名单 | 白名单用户可直接拿 40 代 | `setWhitelist40(user,true)` 后 `eligibleGeneration()` 返回 40 | 权限、开启/关闭、生效范围 |
| 团队数据 | 显示直推人数、列表、团队人数、团队业绩 | 前端递归读取 `getDirectReferrals()`；团队业绩当前按成员 `totalDeposited` 汇总 | 与业务“复投计入、赎回减少”的差异需单独确认 |
| 语言切换 | 支持中繁、英、日、韩、越、马 | 前端有 `zh-CN/en/ja/ko/vi/ms` 多语言切换 | 业务写“中文繁体”，当前默认是简中且部分文案需验收 |
| Admin 配置 | 收益率、手续费、金额规则、锁仓周期、场次、代数、收款钱包可配置 | Admin 后台调用对应 `set*` 方法，Super Admin 才可写 | 权限、保存后链上读取、非法值失败 |
| 用户管理 | 后台显示全部用户和关系树 | 新增 `getAllUsers()` 索引；历史代理用 `syncRegisteredUsers()` 补齐 | 索引数量与 `totalUsers` 一致，历史事件兜底 |

## 3. 已识别的业务差异与验收风险

| 编号 | 差异点 | 当前实现 | 建议验收方式 |
|---|---|---|---|
| GAP-01 | 业务图写“静态收益每天自动发放” | 合约没有自动任务，需用户或 Admin 调 `settleStake()` / `settleStakes()` | 产品确认是否接受手动/后台一键结算 |
| GAP-02 | 业务图写“动态奖励每天 0 点发放” | 合约没有自动任务，需 Admin 调 `settleDynamicRewardForUser(s)`；只能结算已结束本地日 | 产品确认是否需要链下定时任务 |
| GAP-03 | 团队业绩要求“充值进来的 U + 复投也算，赎回相应减少” | 前端团队业绩当前汇总成员 `totalDeposited`，复投不计入，赎回不减少 | 需确认团队业绩口径，必要时改合约或前端统计 |
| GAP-04 | 业务要求中文繁体 | 当前语言包含 `zh-CN` 简体，未单独提供 `zh-TW` | 需确认是否必须增加繁体 |
| GAP-05 | 升级后 5 个收款钱包 | 最近升级后 5 个 `depositReceivers` 均为管理员地址 | 上线前必须设置真实 5 个收款钱包并回归入金轮转 |

## 5. 通用前置条件

1. 浏览器安装钱包插件，并切换到 BSC Mainnet。
2. 普通用户钱包有足够 USDT 和少量 BNB。
3. Super Admin 钱包有足够 BNB，并对提现审批付款保留足够 USDT。
4. Admin 后台已设置：
   - `minAmount=100U`
   - `maxAmount=1000U`
   - `maxPrincipal=1000U`
   - `lockPeriod=30 days`
   - `yieldBps=1%`
   - `withdrawFee=10U`
   - `validVolumeThreshold=1000U`
   - 上午场 `09:00-12:00`
   - 下午场 `14:00-17:00`
   - 5 个真实入金收款钱包
5. 每个测试用例执行后记录：钱包地址、交易 hash、区块号、页面截图、链上读数。

| CFG-014 | 暂停合约 | Super Admin 暂停 | 入金、注册、带单、提现申请、复投等 `whenNotPaused` 写操作失败 |

| ROLE-001 | Manager 权限 | 授予某钱包 Manager | 可进入后台查看，不可保存配置 |
| ROLE-002 | Admin 权限 | 授予某钱包 Admin | 可执行配置、审批、角色操作 |
| ROLE-003 | 撤销自身 Admin | Admin 尝试撤销自己 | 交易失败，提示不能移除自己 |
| ROLE-004 | 转移 Owner | 当前 Owner 转移给新地址 | 新地址拥有 Admin/Manager，旧地址失去权限，默认推荐人随之更新 |
